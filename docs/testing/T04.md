## Flows (real Chromium)
### 1. Key, link fragment, consecutive frames
Steps: generate a key; put its string in `location.hash` of `/s/<sid>?x=1`; `importKeyFromFragment`; create a `FrameSealer` (sender key) and a `FrameOpener` (imported key); seal 5 frames (text, text with emoji and RTL, typing, beat, empty text) and open them in order.
Expected: 43-char key, both `CryptoKey`s non-extractable, address bar loses the fragment but keeps path and query, seqs 1 to 5, each message equals what was sent, `lastSeq` is 5.  Actual: as expected.  Result: PASS

### 2. Padding hides length
Steps: seal `"a"`, 150 x `"x"`, a `typing` message and 300 x `"y"`.
Expected: the first three have the same ciphertext length (272 bytes, 256 + 16 tag), the 300-char text lands in the next bucket.  Actual: 363, 363, 363 and 704 base64url chars.  Result: PASS

### 3. Independent decryption
Steps: seal a frame with a random key, then decrypt it with plain `crypto.subtle.decrypt` using AAD `tincan/v1|<sid>|1`.
Expected: a 256-byte plaintext with a length header and the JSON.  Actual: as expected, so the wire format matches `docs/` and not just the module's own opener.  Result: PASS
